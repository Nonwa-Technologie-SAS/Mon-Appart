# Cadre de priorisation

## Méthode retenue : impact / effort (+ confiance)

Pour chaque item :

| Dimension | Échelle | Signification |
| --- | --- | --- |
| Impact | 1–5 | Valeur utilisateur / risque réduit / revenus **si** monétisation active |
| Effort | 1–5 | 1 = petit, 5 = multi-équipes / multi-sprints |
| Confiance | H / M / L | Qualité des hypothèses (pas de faux objectivisme) |

**Score indicatif** = Impact / Effort (plus haut = plus prioritaire). Ajuster manuellement pour sécurité, légal, dette bloquante.

RICE possible plus tard quand Reach et Confidence sont mesurables. **Sans données d’usage, ne pas inventer Reach.**

## Classes de travail

- **P0** : bloque lancement / confiance / données.
- **P1** : parcours cœur (search, publish, contact).
- **P2** : différenciation (assistant, reco).
- **P3** : croissance / partenaires / monétisation réelle.

## Garde-fous

- Dette sécu / SRE peut battre une feature glossy.
- Une feature « growth » sans tracking fiable = effort gaspillé.
- Paiements réels = validation juridique/contractuelle **hors code**.
